## 🎯 一句话总结

**当前：subagent 沿用通用工具调用的展示样式（JSON dump + 纯文本结果），看不出是 subagent。**
**建议：新建 `SubagentCall.vue` 组件，专门渲染角色徽章、批量子代理列表、每条状态、耗时、综合输出。**

## 📡 当前数据流（已经能跑通的链路）

### 后端 SSE 事件

`ChatEngine.stream_chat_with_messages()` 已经为 subagent 发出和普通工具完全一样的事件结构：

```python
# chat_engine.py 在 tool_call 阶段:
yield json.dumps({
    "type": "tool_call",
    "tool": tc.tool,        # "subagent"
    "action": tc.action,    # ""
    "params": tc.params,    # {role, task, context, mode, tasks, reduce_prompt}
})

# 在 tool_result 阶段:
yield json.dumps({
    "type": "tool_result",
    "tool": tc.tool,           # "subagent"
    "action": tc.action,
    "status": result.get("status", "success"),  # "success" / "partial" / "error"
    "result": result,         # SubagentStrategy 返回的完整 dict
})
```

`SubagentStrategy.execute()` 返回结构（chat_engine 收到的 `result`）：

```python
# 单任务
{
    "status": "success",
    "role": "researcher",
    "task": "调研 X",
    "output": "...",          # 子代理的纯文本输出
    "iterations": 1,
    "elapsed_ms": 8432.1,
    "error": None,
}

# 批量
{
    "status": "success",
    "mode": "parallel",       # sequential / parallel / map_reduce
    "results": [
        {"role": "researcher", "task": "t1", "output": "...", "success": True,
         "elapsed_ms": 8234.5, "iterations": 1, "error": None},
        {"role": "researcher", "task": "t2", "output": "...", "success": True,
         "elapsed_ms": 9123.2, "iterations": 1, "error": None},
    ],
    "reduced_output": "...",  # map_reduce 模式才有
}
```

### 前端 useApi.ts 解析

`composables/useApi.ts` 把 SSE 事件透传成结构化对象：

```ts
// useApi.ts L98-114
} else if (data.type === 'tool_call') {
  onStatus?.({
    type: 'tool_call',
    tool: data.tool,
    action: data.action,
    params: data.params || {},
  })
} else if (data.type === 'tool_result') {
  onStatus?.({
    type: 'tool_result',
    tool: data.tool,
    action: data.action,
    status: data.status,
    result: data.result,
  })
}
```

**好消息**：所有 subagent 特有的字段（`mode`、`results[]`、`reduced_output`、`elapsed_ms`）已经原样传到 `onStatus` 回调，前端拿得到。

### ChatWindow.vue 落地

`components/ChatWindow.vue` L179-196 把事件塞进 Pinia：

```ts
if (status.type === 'tool_call') {
  chatStore.addMessage('tool', JSON.stringify({tool, action, params}))
} else if (status.type === 'tool_result') {
  // 关键: 只取了 result.stdout / content / message / stderr / JSON.stringify(result)
  const detail = result.stdout || result.content || result.message
    || result.stderr || JSON.stringify(result)
  const prefix = resultStatus === 'success' ? '[工具结果]' : '[工具错误]'
  chatStore.addMessage('tool_result', `${prefix} ${tool}.${action}: ${detail}`)
}
```

**问题点**：
- `result.content` 不存在（subagent 返回结构里没有 `content` 字段，只有 `output` 和 `results[]`）
- `result.message` 也不存在
- 实际命中最后一个 fallback `JSON.stringify(result)` —— 把整坨 dict 序列化成字符串塞进 tool_result.content
- batch 模式下 `results[].output` 全部丢失，前端只看到一坨 JSON

### ChatMessage.vue 渲染

`components/ChatMessage.vue` L16-26 的解析逻辑只匹配 `[工具结果] tool: detail`：

```ts
const toolResultInfo = computed(() => {
  const t = props.message.content
  const m = t.match(/^\[(工具结果|工具错误)\]\s*(\S+?):\s*(.*)/s)
  if (m) return { status: m[1] === '工具结果' ? 'success' : 'error', tool: m[2], detail: m[3] }
  return { status: 'info', tool: '', detail: t }
})
```

tool_call 渲染（L151-157）：

## 🚧 当前展示效果（实际看到的样子）

subagent 工具调用会显示成：

```
🔧 subagent.
{
  "role": "researcher",
  "task": "调研 PostgreSQL",
  "context": "用户在做 RAG",
  "mode": "parallel",
  "tasks": [
    { "role": "researcher", "task": "调研 PostgreSQL" },
    { "role": "researcher", "task": "调研 MySQL" }
  ]
}
```

tool_result 会显示成：

```
✅ subagent
{"status": "success", "mode": "parallel", "results": [{"role": "researcher", ...}, ...], "reduced_output": "..."}
```

**三个明显问题**：
1. **看不出是 subagent** —— "subagent" 和 file/bash 显示样式完全一样
2. **看不到角色徽章** —— researcher / coder / reviewer 全是字符串
3. **批量结果被压扁** —— 3 个子代理的 output 揉在一坨 JSON 里，前端无法分别展开
4. **没有耗时** —— `elapsed_ms` 在 JSON 里但没有 UI 强调
5. **map_reduce 综合输出被淹没** —— `reduced_output` 是最有价值的结果，但视觉上和 `results` 平级

## 🎨 改进方案：新增 SubagentCall 组件

### 设计目标

- 角色徽章（researcher/coder/reviewer/summarizer/planner/general）用颜色 + 图标区分
- 模式徽章（sequential / parallel / map_reduce）显示调度方式
- 批量时每个子代理作为可折叠卡片独立显示
- 每张卡片显示：角色、任务摘要、状态、耗时、输出预览
- map_reduce 的 `reduced_output` 单独高亮（这是最终答案）
- 整体仍走 `tool` / `tool_result` 角色，但通过内容检测切到 SubagentCall 组件

### 文件改动清单

```
新增  frontend/src/components/SubagentCall.vue
改动  frontend/src/components/ChatMessage.vue     (添加 subagent 检测分支)
改动  frontend/src/types/index.ts                 (扩展 Message 加 subagent 字段，可选)
改动  frontend/src/components/ChatWindow.vue      (保留原 addMessage 逻辑, 内容已够用)
```

> **改动很小**：现有 SSE 透传已经够用，只需要在 ChatMessage.vue 里加一个 `v-if="isSubagent"` 分支渲染 SubagentCall 组件。

  context?: string

const props = defineProps<{

  map_reduce: { icon: '🗺', color: 'bg-orange-100 text-orange-700', label: 'map_reduce' },

const isBatch = computed(() => Array.isArray(props.data.results))

### ChatMessage.vue 改动（最小化）

在原 `<div v-if="isTool && toolInfo">` 分支前加一个 subagent 检测：

```vue
<!-- 新增: subagent 专用渲染 -->
<SubagentCall
  v-else-if="isTool && isSubagentToolCall"
  :data="subagentCallData"
  variant="call"
/>
<SubagentCall
  v-else-if="isToolResult && isSubagentToolResult"
  :data="subagentResultData"
  variant="result"
/>

<!-- 保留: 旧工具调用 -->
<div v-if="isTool && toolInfo" class="flex items-start gap-2 text-xs">
  <!-- ...原有逻辑... -->
</div>
```

新增两个 computed：

```ts
const isSubagentToolCall = computed(() =>
  isTool.value && toolInfo.value?.tool === 'subagent'
)
const isSubagentToolResult = computed(() => {
  if (!isToolResult.value) return false
  // tool_result.content 是 "[工具结果] subagent: {...}"
  return /^[\[【](?:工具结果|工具错误)[\]】]\s*subagent[\s:]/i.test(props.message.content)
})

const subagentCallData = computed<SubagentData>(() => {
  const info = toolInfo.value!
  return {
    kind: 'subagent',
    role: info.params?.role,
    task: info.params?.task,
    context: info.params?.context,
    mode: info.params?.mode,
    status: 'success',
  }
})

const subagentResultData = computed<SubagentData>(() => {
  // 从 "[工具结果] subagent: {...JSON...}" 提取 JSON
  const m = props.message.content.match(/\[(工具结果|工具错误)\]\s*subagent:\s*([\s\S]+)/)
  if (!m) return { kind: 'subagent', status: 'error' }
  try {
    return { kind: 'subagent', ...JSON.parse(m[2].trim()) }
  } catch {
    return { kind: 'subagent', status: 'error' }
  }
})
```

## 🧩 完整数据流（改进后）

```
用户输入
   ↓
ChatEngine.stream_chat_with_messages
   ├─ Phase 1: 流式 thinking + text + tool_use_start
   ├─ Phase 2: tool_call SSE ──────────────────────────────┐
   │         {"type":"tool_call","tool":"subagent",        │
   │          "params":{"mode":"map_reduce",...}}          │
   │                                                       ▼
   │                                            useApi.onStatus → ChatWindow
   │                                                       ↓
   │                                            addMessage('tool', JSON.stringify(...))
   │                                                       ↓
   │                                            Pinia store: messages[]
   │                                                       ↓
   │                                            ChatMessage.vue 检测 tool==='subagent'
   │                                                       ↓
   │                                            渲染 <SubagentCall variant="call" />
   │
   ├─ Tool 执行 → SubagentStrategy → SubagentOrchestrator → N 个子代理并行
   │
   ├─ tool_result SSE ────────────────────────────────────┐
   │         {"type":"tool_result",                       │
   │          "tool":"subagent","status":"success",        │
   │          "result":{mode, results[], reduced_output}}  │
   │                                                       ▼
   │                                            ChatWindow 解析 → addMessage('tool_result', ...)
   │                                                       ↓
   │                                            ChatMessage 检测 subagent tool_result
   │                                                       ↓
   │                                            渲染 <SubagentCall variant="result" />
   │
   └─ Phase 2: 后续流式 text（主 LLM 拿到结果后继续生成最终回复）
```
