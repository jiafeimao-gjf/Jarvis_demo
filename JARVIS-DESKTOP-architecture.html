01进程与代码分层

四个平级目录，边界由静态检查与单元测试共同锁死。任一越界都会在 npm run typecheck 或 npm test 阶段暴露。

窗口只能由一个地方创建

业务模块禁止出现 new BrowserWindow(，由 window-manager.ts 独占。测试会静态扫描并失败。

shared/ 是编译期契约

被主进程、preload、渲染层三向引用，因此不得 import electron 或 node:*（连同 Vitest 一起跑不了）。

常量跨文件一致

APP_ID / PRODUCT_NAME / APP_SCHEME / MINIMUM_SYSTEM_VERSION 必须与打包配置一致，只改一处测试立刻失败。

渲染层无系统能力

一切系统调用走 window.api，经 useDesktop 封装。IPC 返回判别联合而非抛出异常。

02IPC 契约：单一事实来源

新增一条通道必须同时改三处。这不是约定，是类型系统强制的——校验器表是 Record<Channel, Validator>，漏写就编译不过。

03运行时链路：开发态 vs 打包态

两条路径的同源条件完全不同：开发态有 vite proxy 兜底，打包态没有代理、只有 file://。但它们在代码里共用同一套地址解析（lib/api-client），差别仅在于基址是否为空。

修复前的对照：打包态下 fetch('/api/status') 得到 TypeError: Failed to fetch（被解析成 file:///api/status）。这条断言已固化为回归探针，见 npm run verify:backend。

04主进程启动时序

顺序有硬约束。分界线两侧访问的系统能力可用性不同，调换会直接崩在启动阶段。

05打包与验收链路

每一步都有对应的脚本，验收退出码可直接接进 CI 判断，不靠人眼看。

脚本作用
scripts/make-dmg.sh一键产出 dmg + zip，注入国内镜像、临时配置固定架构、失败时兜底，并透传验收退出码
scripts/verify-release.sh四项结论：签名、架构、Gatekeeper、公证票据。支持 --expect-adhoc
scripts/smoke-test.sh把产物真的启动一次：进程存活、窗口显示、日志命中标记、正常退出

06已修复：打包态后端链路

问题：打包态下所有 /api 与 /ws 请求失效

打包出来的 .app 装到别的机器上界面能开，但每一个后端请求都失败 —— 现象与"后端没启动"完全一致。根因不是某一行写错，而是相对路径隐含了"同源"这个前提：file:// 页面下 /api/chat 被解析成 file:///api/chat，请求根本没离开应用。

实际涉面比看上去大：全仓 74 处 fetch，其中 69 处各自硬编码 /api 前缀。开发态之所以看起来一切正常，是 5173 的代理在替它们兜底。

采用的方案（原三个候选中选第 2 项）：主进程经 additionalArguments 下发后端基址 → preload 暴露 window.api.backendOrigin → 渲染层统一经 lib/api-client 补全为绝对地址。另两个候选被否：protocol.handle 反代承载不了 WebSocket 升级（等于只解决一半）；session.setProxy 对 file:// 无效（不走网络栈代理）。

Jarvis_demo 的 .env / config.pyCORS 增放行 5173（必需）与 null（预防性）
一条被实测推翻的初始判断：原以为打包态必须让后端放行 Origin: null。实测（Electron 44 / Chromium 152）file:// 页面发出的 fetch 不携带 Origin 头，因此并不触发 CORS 检查 —— 在未放行 null 的旧配置下，打包态直连同样成功。相反 5173 是必需的：开发态现在是真正的跨源请求，少放行它就报 TypeError: Failed to fetch，而后端日志里连访问记录都不会有。
回归防护：tests/unit/renderer-api-guard.spec.ts 扫描渲染层源码，禁止裸 fetch('/api…')、禁止绕过封装直接摸 window.api、禁止在调用点内联 window.location.host；tests/unit/backend-path.spec.ts 覆盖地址补全规则；npm run verify:backend 在真实 Electron 里验证两种形态的连通性（打包形态的裸相对路径必须失败，充当回归探针）。
仍在的外部阻塞：无 Apple Developer 账号，签名/公证只能走 ad-hoc（spctl 必然 rejected）；electron-builder.yml 的 publish.owner 仍是占位值 —— 自动更新链路未接通。
